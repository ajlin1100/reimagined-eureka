Working with Data

Learn how latency impacts heavy analytical workloads in virtual environments and follow essential workflow guidelines to optimize software performance and prevent data loss.

⚡︎ Understanding Data Location & Latency

When working in vSmith, application processing occurs on physical servers located in the Smith IT Data Center in College Park. However, your personal files reside on your local machine or external cloud storage providers (Google Drive, Box, Dropbox).

Standard Documents vs. Analytical Datasets

Opening basic spreadsheets or word documents across network drives causes minimal delay. However, intensive analytical tools perform frequent read/write cycles across the network, leading to severe latency and slow performance if files remain stored remotely during execution.

Tableau IDEA Palisade Decision Tools Large Excel Data

Recommended High-Performance Workflow

1. Copy the analytical file locally to the session's Documents folder.
2. Run your analysis and calculations inside vSmith.
3. Save changes and copy the file back to cloud/local storage before ending your session.

📂︎ File Transfer & Execution Guide

Method A: Standalone Applications

  1. Launch your application from Omnissa Horizon to connect to an assigned server.
  2. Leave the application open, then launch File Explorer from Omnissa Horizon so it opens on the same server.
  3. In File Explorer, select This PC from the left menu.

Method B: Student Desktop Session

  1. Log in to the Student Desktop session normally.
  2. Open Windows Explorer by clicking the Start Menu and choosing Student Desktop / File Explorer.

Executing Your Work via File Explorer

  1. Locate Source Files: If mapped via TerpDrives, access your cloud drive letters or mapped local computer user profile.
  2. Copy to Session: Drag or copy/paste target datasets into the virtual machine's local Documents folder.
  3. Perform Analysis: Open your application, load the dataset from the Documents folder, complete your assignment, and save your changes.
  4. Copy Back Output: Drag or copy/paste the updated files from Documents back to TerpDrive or your local host machine.

🚨︎ CRITICAL NOTICE: Unsaved Session Data is Permanently Lost

YOU MUST COPY YOUR COMPLETED FILES OFF THE VIRTUAL MACHINE BEFORE LOGGING OFF.

Virtual desktops and application servers are dynamically destroyed upon session logoff. Anything left in the local Documents folder will be immediately deleted. Smith IT cannot recover un-copied or lost files.

⚠︎ Critical Data Loss Warning

Do not attempt to save files directly to the vSmith application server or desktop machine. Because vSmith uses non-persistent virtual environments, all data saved in non-approved local folders will be permanently deleted when you log out or disconnect. The virtual desktop Recycle Bin is disabled, so deleted or lost files cannot be recovered.

⏱︎ Inactivity & Disconnect Session Rules

To ensure server capacity for all users, idle sessions are automatically terminated. Always save your work and manually log off when finished.

⏳ 30-Minute Inactivity Timeout

Students are automatically logged off if no mouse or keyboard activity is detected for 30 minutes. Unsaved work will be lost.

🔌︎ 15-Minute Disconnect Limit

If you close your client window or lose internet connection without explicitly logging off, your session stays active for only 15 minutes before being force-closed.

🚫︎ Disabled Recycle Bin

The Recycle Bin is disabled on all virtual desktops. Files deleted inside vSmith cannot be restored.

TerpDrive Cloud Integration

Connect your cloud storage providers directly to Windows Explorer in vSmith, SmithApps, and Van Munching Hall lab computers to open and save files as if they were on a local drive.

☁︎ What is Terpdrive?

Terpdrive links your personal or campus cloud storage accounts through Kumo. Once authorized, your cloud drives seamlessly map as drive letters in Windows Explorer whenever you log into any vSmith session, SmithApp, or campus computer lab.

📁︎ Included Student & Staff Cloud Storage

• Box Account: Every student, faculty, and staff member receives a 50 GB account (box.umd.edu).
• Google Drive: Provided via your official campus email account (@umd.edu) with 256 GB.

🔗︎ Authorizing Cloud Providers

Log into Kumo, select your desired cloud provider, and click Authorize. You can return at any time to remove or adjust authorization.

Box

1. Select Box and click Use Single Sign On (SSO).
2. Enter your campus email (e.g., jdoe@umd.edu) and click Authorize.
3. Complete standard UMD login with your Directory ID.

Google Drive

1. Select Google Drive and click Authorize.
2. Log in with your UMD Google account (or select your active session).
3. Grant permissions for Kumo/Terpdrive to display files.

Dropbox

1. Select Dropbox and click Authorize.
2. Log in using your Dropbox credentials.
3. Grant permission for Kumo/Terpdrive to access and display files.

💡︎ Accessing Mapped Drives

Once authorized, open Windows Explorer / File Explorer in vSmith or a VMH lab machine. Your linked cloud services will automatically appear mapped directly to individual drive letters under This PC.
